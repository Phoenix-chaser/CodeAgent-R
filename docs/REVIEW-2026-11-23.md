## 1. 判分只看退出码

**问题。** 候选通过的条件是 pytest 退出码为 0，没有检查测试是否真的执行。

**复现。** 用同一组候选分别交给修复前后的 grader：

| 候选 | 修复前 | 修复后 |
| --- | --- | --- |
| 参考解 | strict_pass | strict_pass |
| 模块顶层 `os._exit(0)` | **strict_pass** | strict_fail |
| 被测函数被调用时执行 `pytest.skip()` | **strict_pass** | strict_fail |
| 把参数化列表改短，少收集用例 | **strict_pass** | strict_fail |
| 用 diff 新增根目录 `conftest.py`，把用例全标成 skip | **strict_pass** | invalid |
| 导入时改写公开测试文件 | **strict_pass** | strict_fail |

**修复。** 参考解先在同一隔离环境里跑一遍，它执行到的测试集合就是每一层“必须跑完的测试”。候选必须同时满足：退出码为 0，汇总行的 passed 数等于预期且没有 skipped、deselected、xfailed、error，junit XML 里的用例集合与预期完全一致并且全部通过。`allowed_paths` 从 `*.py` 收窄为题目指定的主模块。私有测试改为公开层跑完之后才注入，公开层执行期间磁盘上没有私有测试；公开层跑完后复核工作区文件哈希。

**证据。** [grader](../src/agentlab/benchmark/grader.py)；回归测试在 [test_grader_hardening.py](../tests/test_grader_hardening.py)。104 道题的导出流程在新 grader 下重新跑过：参考解通过 104/104，原始缺陷复现 104/104。

## 2. 候选代码直接在宿主机执行

**问题。** 模型生成的代码直接在宿主机上运行，唯一的防护是按变量名过滤环境变量。超时只杀 pytest 这个直接子进程。

**复现。** 修复前交给候选的环境里有 `OPENAI_KEY`（名字不含被过滤的关键词）、`HOME`、`DISPLAY`、`DBUS_SESSION_BUS_ADDRESS` 等。候选在导入时可以写入工作区。

**修复。** [隔离模块](../src/agentlab/runtime/isolation.py)在独立的 bootstrap 进程里、加载任何不可信代码之前完成三件事：

- **Landlock**（Linux 5.13 起可用，不需要 root 或容器）：工作区只读，只放行解释器、标准库和 site-packages 的读权限，真实 HOME、`/etc`、`/proc` 不可读，只有解释器和共享库可执行。ABI ≥ 4 时拒绝全部 TCP connect 和 bind。
- **rlimit**：CPU 时间、地址空间、单个文件大小、进程数、core dump。
- **环境**：按白名单构造，HOME 与临时目录指向沙箱内的可写目录。

超时沿用 `runtime.exec` 已有的进程组清理。root 默认拒绝执行。

**实测。** Landlock 模式下，读真实 HOME、改工作区文件、读 `/etc/passwd`、读 `/proc/self/environ`、连 TCP、执行 `/bin/sh` 全部返回 `PermissionError`；`sys.executable` 子进程和标准库导入正常。指数型 fork 被限制在额外 64 个进程。`RLIMIT_CPU=1` 时死循环在 1 秒被终止。

**降级。** Landlock 不可用时退回到 rlimit 加清洁环境。实测这种模式下真实 HOME 可读、工作区可写、TCP 可连，并且候选能通过 `/proc/<父进程 pid>/environ` 读到判分进程的真实环境变量。判分详情的 `execution.isolation` 如实记录实际模式；`AGENTLAB_SANDBOX=required` 时改为拒绝执行。

**没有解决的部分。** 容器后端仍未实现，`doctor` 现在如实报告它不可用。另行 `setsid` 的孙进程不受进程组清理约束。Landlock 只覆盖 TCP。同一个 pytest 进程内的对抗性代码仍能伪造输出。

## 4. bootstrap 按题而不是按来源组重采样

## 8. CI 首次运行发现：沙箱放行规则不适应独立构建的 Python

**问题。** 改动推送后，CI 的两个测试任务各有 40 项失败。沙箱的放行规则按 `sysconfig` 推断共享库目录。GitHub runner 上的 Python 是独立构建的，有自己的 `lib` 目录，libc 却在系统目录里，没有被打开放行。结果是解释器在沙箱里起不来，所有判分都变成基础设施错误。本机没有暴露这个问题，因为本机系统 Python 的库目录恰好就是系统库目录。用 conda 或独立构建的 Python 的服务器会遇到同样的情况。

**复现。** 在临时目录里装一个独立构建的 Python 3.12，用它构造沙箱策略：`error while loading shared libraries: libpthread.so.0: cannot open shared object file`，退出码 127。同一个脚本用系统 Python 则通过。

**修复。** 读取解释器的 ELF 头得到动态加载器，让加载器报告解释器和每个扩展模块实际依赖的共享库，放行这些库所在的目录。系统库目录只给读权限，`git` 在沙箱里仍然不可执行。判分因为进程没起来而失败时，错误信息带上它的 stderr。

**自检。** `agentlab doctor` 新增 `sandbox.selftest` 一行，它在沙箱里真实启动一次解释器并导入判分用到的库。`env` 阶段运行同一个自检，失败即停。

**验证。** 修复前后用同一个独立 Python 对比：修复前无法启动，修复后通过，HOME 不可读、工作区只读、TCP 拒绝等保证不变。用独立构建的 Python 3.12 建一个临时虚拟环境，布局与 CI runner 相同，全量测试 532 项通过、3 项跳过，跳过的是依赖 transformers 的测试。

**教训。** 在本机通过不等于可移植。隔离规则依赖运行环境时，要在不同的安装方式下各验证一次，并在目标机器上提供自检。第 2 节的实测只覆盖了系统 Python，这一节补上了另一种布局。

## 9. 以压缩包部署时，`env` 阶段会停在一个测试上

**问题。** 项目除了 `git clone`，也以 tar 包上传到服务器，解包后的目录没有 `.git`。把 GitHub 上的版本导出成这样的目录再跑全量测试，有 1 项失败：`test_evidence_files_are_not_gitignored` 在当前目录里调用 `git check-ignore`，得到的退出码是 128。`env` 阶段运行全量测试，流水线会在这里停住。CI 和本机都在 git 仓库里运行，所以没有暴露。

**修复。** 这个测试改为在临时仓库里复制 `.gitignore` 再检查，并增加一组应当被忽略的对照路径。导出成不带 `.git` 的目录后，全量测试通过。

**教训。** 每一种实际使用的部署方式都要单独验证一遍。

## 10. 长流程里沙箱进程会突然全部起不来

**问题。** 把 104 道题的审计放在一个进程里跑，到末尾时每一次判分都报 `pytest could not start: [Errno 7] Argument list too long`。抓到的现场是：传给沙箱的策略参数有 131819 字节，超过了 Linux 对单个参数的上限 131072 字节，而正常情况下只有约 1.4KB。

**原因。** 第 8 节的修复给解释器规则表加了进程内缓存，`build_policy` 却直接在这张缓存的列表上追加本次工作区的规则。每构造一次策略多 3 条，一个进程里判分约 300 次后就超限。这个问题随第 8 节的修复一起进入了提交 `c81c589`。

**为什么之前没发现。** 测试套件在一个进程里只调用几十次，14 道内置题的审计也远不到阈值。服务器上的采集、选型和终评都是一个进程里连续判分几百次，会在中途全部变成判分失败。

**修复。** 缓存改为返回不可变的元组，`build_policy` 每次新建列表。新增回归测试：连续构造 60 次策略，规则条数不变，策略参数保持在上限的十分之一以下。用同一个 104 题审计重跑，约 880 次沙箱启动全部成功。

**教训。** 只在有状态的长时间运行中才出现的问题，短测试发现不了。凡是“缓存 + 每次调用都修改返回值”的写法，都要让缓存返回不可变对象。
